# Overlay guide

The overlay is a **private** repository that holds everything the kit must not: your preferences,
your machine, the people you work with, your organizations' conventions and your projects' state.
The kit ships its structure as a template in `templates/overlay/`.

## Layers

```text
kit       lloping-llama: generic skills, agents, hooks, workflows
  me      you: preferences, machine, people
    org   one organization: conventions, repository policy
      project  one project: state, decisions, runbooks, drafts, reports
```

A more specific layer wins: a project rule overrides an org convention, which overrides your
preferences, which override the kit's defaults.

## Structure

```text
overlay/
├── CLAUDE.md                     entry point, imported from ~/.claude/CLAUDE.md
├── profiles.yaml                 per-repository profiles (see Profiles)
├── me/
│   ├── preferences.md            how you work with agents
│   ├── machine.md                your computer (generated by a collector)
│   ├── people.md                 people you work with, and who may get messages without review
│   └── collect-machine/          collectors for Linux, macOS and Windows
├── orgs/<org>/
│   ├── conventions.md            branching, labels, CI, releases, docs
│   └── repo-policy.md            desired state of every repository (align-repo)
├── projects/<project>/
│   ├── state.md                  current state: single source, kept current
│   ├── decisions.md              decisions, append-only
│   ├── runbooks/                 procedures with complete commands
│   ├── drafts/                   messages and documents waiting for review
│   └── reports/                  agent reports
├── todos/                        your to-do list
└── archive/                      finished material, kept
```

## Set up

1. Create a private repository, e.g. `<you>/agent-overlay`, and copy the contents of
   `templates/overlay/` into it.
2. Rename `orgs/example-org/` and `projects/example-project/`; copy them for more orgs and
   projects.
3. Generate your machine file with the collector for your OS:

    === "Linux"

        ```sh
        bash me/collect-machine/linux.sh > me/machine.md
        ```

    === "macOS"

        ```sh
        sh me/collect-machine/macos.sh > me/machine.md
        ```

    === "Windows"

        ```powershell
        powershell -ExecutionPolicy Bypass -File me\collect-machine\windows.ps1 > me\machine.md
        ```

    The collectors only read. They print OS, shell, terminal, editor, a hardware summary and the
    versions of common tools. They print no host name, user name or home path unless you pass
    `--with-identity` (`-WithIdentity` on Windows), and they replace your home path and user name
    in tool output. Then add what a script can't know under "Known oddities".

4. Fill in `me/preferences.md`, `me/people.md`, `profiles.yaml` and the org and project files.
   Every file says what goes into it.
5. Import the overlay in `~/.claude/CLAUDE.md`:

    ```text
    @~/path/to/agent-overlay/CLAUDE.md
    ```

## People and messages

`me/people.md` has one section per person, with a `send` field:

- `draft` (default): agents only prepare unsent drafts; you review and send.
- `auto`: agents may send messages to this person directly.

`auto` is allowed **only for single persons**, never for channels, groups or mailing lists. Every
automatically sent message ends with a note such as:

```text
(Sent automatically by Claude on behalf of <your name>, without <your name>'s review; please treat
with care.)
```

## Rules for the overlay

- **No secrets.** No tokens, passwords, kubeconfigs or `.env` files; runbooks ask for credentials at
  run time.
- **Decisions are append-only.** Supersede a decision with a new line; don't edit old ones.
- **State is current.** `state.md` describes now; history lives in git and `archive/`.
- **Keep it private.** The overlay is yours; the kit is public.
